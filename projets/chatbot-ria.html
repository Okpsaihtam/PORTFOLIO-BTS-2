Un chatbot qui audite les applications web

Intégrer un modèle de langage dans une application Flask pour évaluer une RIA et produire un rapport

Avant-match

Contexte et problématique

Une RIA (Rich Internet Application) est une application web riche, qui se comporte comme un logiciel installé. Les évaluer demande de regarder à la fois le code, les performances et l'expérience utilisateur, ce qui prend du temps à un développeur.

J'ai voulu construire un assistant capable de faire un premier diagnostic et de l'expliquer en langage clair, pour une personne technique ou non.

Comment utiliser un modèle de langage pour produire une évaluation utile et fiable d'une application web, sans en faire une boîte noire ?

Le plan de jeu

Objectifs

  • Intégrer une API de modèle de langage dans une vraie application
  • Structurer une analyse en critères mesurables
  • Générer un rapport exploitable en équipe
  • Mettre l'application en ligne
Mon poste

Missions principales

  • Concevoir le prompt système et la grille d'évaluation (architecture, performances, accessibilité, sécurité, UX)
  • Développer le serveur Flask et ses routes de conversation et de rapport
  • Récupérer et résumer le contenu de la page analysée avant de l'envoyer au modèle
  • Créer l'interface de chat côté navigateur
  • Générer le rapport PDF et déployer l'application sur Render
Le déroulé

Étapes clés

  1. Cadrage

    Choix des critères d'évaluation et du format de réponse attendu, pour que chaque analyse suive la même grille.

  2. Serveur et API

    Routes Flask, appel au modèle de langage, clé d'API stockée dans une variable d'environnement côté serveur.

  3. Interface de chat

    Page HTML, CSS et JavaScript : envoi des messages, affichage des réponses, état de chargement.

  4. Rapport PDF

    Mise en forme des résultats par critère avec une recommandation prioritaire, téléchargeable en un clic.

  5. Déploiement et essais

    Mise en ligne sur Render, essais sur plusieurs sites et ajustement du prompt quand les réponses étaient trop vagues.

Numérique responsable

  • Messages limités en longueur et réponses plafonnées en jetons : chaque appel au modèle consomme moins d'énergie.
  • Le contenu de la page est résumé avant l'envoi, au lieu de transmettre tout le code source.
  • Pas de base de conversations : les échanges ne sont pas stockés sur le serveur.

Bilan réflexif

Ce que j'ai appris

Un modèle de langage est un composant comme un autre : il faut encadrer ses entrées, vérifier ses sorties et prévoir le cas où il se trompe.

Difficulté et solution

Les premières évaluations étaient trop générales. J'ai imposé une grille de critères et un format de réponse précis dans le prompt système, ce qui a rendu les rapports comparables.

Pour aller plus loin

Croiser l'avis du modèle avec des mesures objectives (Lighthouse, validateur W3C) et ajouter un historique des analyses.

Ce projet confirme mon orientation vers le développement IA : j'aime relier un modèle de langage à un besoin concret et en faire un outil que d'autres peuvent utiliser.
